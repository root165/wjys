## 一、巡检业务的统一模型

巡检计划是“规则”，巡检任务是按规则生成的“某一天的一次执行实例”，巡检任务生成时会快照当时有效的巡检点和检查项，后续修改配置不追溯修改已经生成的任务。

### 1. 角色职责

| 角色 | Web 管理端 | 移动端 | 巡检任务权限 |
| --- | --- | --- | --- |
| 系统管理员 | 维护账号、角色、菜单、组织、字典、日志；查看和配置全局数据 | 不参与现场执行 | 不能领取、不能填写、不能提交巡检任务 |
| 设备管理员 | 设备台账、巡检计划、巡检配置、报修受理、派单、验收、维保审核 | 可按业务需要查看 | 默认不领取巡检任务 |
| 巡检员 | 查看必要的任务监控信息 | 查看待领取/已分配任务、扫码核验、填写检查项、上传照片、提交异常 | 可以领取和执行 |
| 维修工 | 查看和处理报修工单 | 接单维修、登记原因、方案、停机时长、备件消耗 | 不领取巡检任务 |
| 企业管理者 | 查看设备、巡检、故障和统计分析 | 只读查看（如开通） | 不能领取、不能填写 |

“执行人 #1”不再作为默认业务规则。历史演示数据中的管理员执行人已清理；新任务默认可以没有执行人，等待符合条件的巡检员领取。

### 2. 计划执行时间

巡检计划必须包含“执行时间”。它表示计划日当天允许生成任务的时刻，例如每天 09:00；到达该时刻后，调度器生成当天任务。执行时间不是任务完成截止时间，生成后超过 30 分钟仍未领取或未完成，任务标记为逾期，但仍允许补交。

计划日期范围按自然日处理：开始日和结束日均包含，结束日有效到当天 23:59:59。当前支持每日、每周、每月周期；手动生成也必须满足计划日期和周期规则，不能任意补造不属于计划周期的任务。

### 3. 任务派发方式

计划创建和编辑时可以选择：

1. **自行领取**：默认方式，任务生成时执行人为空；启用状态的巡检员在移动端领取，领取成功后从“待领取”变为“执行中”。
2. **固定执行人**：只能选择启用中的巡检员；任务生成时直接分配给该人员。
3. **设备责任人**：计划内所有设备必须解析到同一个启用中的巡检员责任人；多个责任人时拒绝保存或生成，避免任务责任不清。
4. **部门轮询**：选择一个部门，在该部门启用中的巡检员中按当天活动任务数和用户 ID 做稳定的负载均衡。

系统管理员不能通过接口绕过角色限制领取任务。Web 端负责计划配置、生成和监控，移动端负责巡检员现场领取与执行。

### 4. 状态与一致性

- 任务状态：待领取、执行中、已完成、逾期、已取消。
- 同一个计划同一个计划日最多生成一条任务，数据库和服务层同时保证幂等。
- 调度器使用 Redis `inspection:generate` 锁；锁带随机 token，释放时只允许锁持有者删除。
- 数值型检查项超出上下限自动形成异常；配置了“必须拍照”的检查项，提交时必须绑定照片。
- 巡检异常进入 M04 报修链路；移动端离线提交必须使用客户端幂等键，网络恢复后不得重复生成记录。

## 二、审计发现及已统一修正

| 问题 | 处理结果 |
| --- | --- |
| 计划没有执行时刻，调度逻辑无法表达“当天何时生成” | 增加 `execute_time`，调度器按计划时刻生成 |
| 新任务默认绑定系统管理员/用户 #1 | 新任务默认执行人为空；固定派发时只允许巡检员 |
| 系统管理员可以领取和提交巡检任务 | Web 与移动接口均收紧为巡检员角色 |
| 巡检计划没有可选执行人/派发方式 | 增加自行领取、固定人员、设备责任人、部门轮询，并提供候选人员接口 |
| 计划只能新增，缺少完整编辑 | 增加计划编辑接口和弹窗页面，编辑全部计划字段及点位 |
| 手动生成可绕过周期日期 | 手动生成和自动生成共用日期、周期、有效期校验 |
| 设备责任人派发可能产生多人责任冲突 | 生成前校验所有点位设备责任人必须唯一且有效 |
| 停用计划的历史任务可能一直不逾期 | 逾期扫描覆盖历史计划；停用只阻止新任务生成，不改变历史任务结算规则 |

## 三、当前验证结果

- 后端本地测试：18 个测试全部通过，Flyway 迁移已验证。
- 前端生产构建：通过，当前仅保留既有的大 chunk 提示。
- 远端服务：前端、后端、MySQL、Redis、MinIO 容器均健康；前端和后端健康接口返回 200。
- 远端巡检数据：演示计划已切换为自行领取，未再保留管理员作为新任务执行人；已领取的巡检员任务仍保留其正常执行状态。

## 四、仍需明确的交付边界

1. 详细设计还描述了小时级周期和“提前 24 小时生成”策略，而当前实现和页面采用“每日/每周/每月 + 到执行时刻生成”。如果业务确实需要小时级巡检，应单独扩展周期枚举、计划时间表达式和任务唯一键，不能直接复用当前日期字段。
2. 当前 `plan_time` 是计划日，具体生成时刻由计划的 `execute_time` 表达。若后续需要秒级审计、补班次或同日多次巡检，应增加任务实际执行时间字段，而不是把多个任务塞进同一个日期键。
3. Android APK/AAB 真机、杀进程、弱网、离线照片、Storage 容量等验证仍需在真实移动设备或远端构建环境执行；它们不应作为 Web 端业务规则的默认行为。
